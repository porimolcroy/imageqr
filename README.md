=== QR স্টুডিও — সেটআপ (একবারই, প্রায় ১০ মিনিট) ===

ফাইলগুলো কোন কাজে:
  index.html  → সাইন আপ / লগইন পেজ (সাইটের প্রথম পেজ)
  main.html   → লগইনের পর ড্যাশবোর্ড
  qr.html     → QR কোড জেনারেটর (শুধু লগইন করা ইউজার খুলতে পারবে; QR এর রং, ছবি, কলাম, প্রিন্ট সব এখানে)
  admin.html  → অ্যাডমিন প্যানেল (ইউজার দেখা, ব্লক/আনব্লক, পাসওয়ার্ড রিসেট)
  style.css   → সব পেজের ডিজাইন
  config.js   → একমাত্র সেটিং ফাইল (Web App URL + সাইটের নাম)
  Code.gs     → Google Sheet-এর ব্যাকএন্ড (GitHub-এ দেওয়ার দরকার নেই)

পেজগুলো নিজেরাই একে অপরের সাথে লিংক করা আছে:
  index → main → qr, আর সব পেজ থেকে লগআউট করলে index-এ ফেরে।

ধাপ ১: Google Sheet ও ব্যাকএন্ড
 1. sheets.new খুলে একটি নতুন Google Sheet বানান (নাম: Users DB)।
 2. মেনু: Extensions > Apps Script
 3. ডিফল্ট কোড মুছে Code.gs ফাইলের সব কোড পেস্ট করুন।
 4. উপরের লাইনে ADMIN_PASSWORD = "admin123" বদলে নিজের পাসওয়ার্ড দিন। Save (Ctrl+S)।
 5. Deploy > New deployment > ধরন (গিয়ার আইকন) "Web app"
      Execute as: Me
      Who has access: Anyone
    Deploy চাপুন, অনুমতি (Authorize) দিন। ("Advanced > Go to project" এসে Allow করতে হতে পারে।)
    (অনুমতির তালিকায় "ইমেইল পাঠানো" থাকবে: সাইন আপের পর User ID এবং ভুলে গেলে লগইন তথ্য ইমেইলে পাঠানো হয়।)
 6. যে "Web app URL" (https://script.google.com/macros/s/.../exec) পাবেন তা কপি করুন।

ধাপ ২: config.js
 config.js খুলে PASTE_YOUR_WEB_APP_URL_HERE-এর জায়গায় ওই URL বসান।
 চাইলে একই ফাইলে সাইটের নাম ও ট্যাগলাইনও বদলাতে পারবেন (SITE অংশ)।
 (ইমেইলে যে নাম যাবে তা Code.gs-এর SITE_NAME থেকে আসে, সেটাও মিলিয়ে নিন।)

ধাপ ৩: GitHub
 1. github.com এ নতুন repository বানান (Public)।
 2. এই ৬টি ফাইল আপলোড করুন (Add file > Upload files):
      index.html, main.html, qr.html, admin.html, config.js, style.css
 3. Settings > Pages > Source: "Deploy from a branch" > main > / (root) > Save
 4. কয়েক মিনিট পর https://আপনার-নাম.github.io/রিপোর-নাম/ এ সাইট চালু হবে।
    অ্যাডমিন পেজ: .../admin.html

=== ব্যবহার ===
 - নতুন ইউজার: সাইন আপ দিলে User ID শুধু তার ইমেইলে যায় (স্ক্রিনে দেখায় না)। ইমেইল থেকে ID কপি করে
   "অ্যাকাউন্ট চালু করুন" ঘরে বসালে অ্যাকাউন্ট চালু (Pending → Active) হয়ে ড্যাশবোর্ডে ঢোকে।
   ইমেইল না এলে "আবার পাঠান" চাপুন। এতে ভুয়া ইমেইল দিয়ে কেউ অ্যাকাউন্ট চালু করতে পারে না।
 - QR এর রং: qr.html এর নিচের বারে "🎨 QR এর রং" থেকে কোডের রং ও ব্যাকগ্রাউন্ডের রং বেছে নেওয়া যায়, বা তৈরি রংয়ের
   বাটন চাপা যায়। রং ব্রাউজারে মনে থাকে। কোড গাঢ় ও ব্যাকগ্রাউন্ড হালকা রাখলে স্ক্যান ভালো হয় (পেজ নিজেই সতর্ক করে)।
 - Google Sheet-এর "Users" ট্যাবে সব ইউজারের তথ্য জমা হয়। এই Sheet কাউকে Share করবেন না।
 - ব্লক করতে: admin.html থেকে, অথবা Sheet-এর Status কলামে Blocked লিখুন (আনব্লক: Active)।
   ব্লক করা ইউজার কয়েক মিনিটের মধ্যে আপনা-আপনি লগআউট হয়ে যায়।
 - User ID/পাসওয়ার্ড হারালে: লগইন পেজে "ভুলে গেছেন?" > ইমেইল দিন > তথ্য ওই ইমেইলের inbox-এ যায়।
   একই ইমেইলে ৫ মিনিটে একবার। ফ্রি Gmail-এ দিনে প্রায় ১০০টি ইমেইল পাঠানো যায়। Spam ফোল্ডারও দেখতে বলুন।
 - ইমেইল না পৌঁছালে অ্যাডমিন পেজ থেকে নতুন পাসওয়ার্ড সেট করে দিন।
 - Excel ফাইল চাইলে: Sheet-এ File > Download > Microsoft Excel (.xlsx)।
 - Code.gs বদলালে: Deploy > Manage deployments > Edit > New version > Deploy (URL একই থাকে)।

=== জেনে রাখা ভালো ===
 1. পাসওয়ার্ড Sheet-এ সাধারণ লেখা (plain text) হিসেবে জমা হয় (hash করা হয় না), আর অ্যাডমিন সেটা দেখতে পায়।
    তাই এই সিস্টেমে এমন ইউজারদের দিন যাদের পাসওয়ার্ড অন্য কোথাও ব্যবহার হয় না — ইউজারদের বলে দিন
    তারা যেন নিজের ইমেইল/ব্যাংকের পাসওয়ার্ড এখানে না দেয়।
 2. GitHub Pages স্ট্যাটিক হোস্টিং, তাই qr.html-এর লগইন-গেট "ব্রাউজারে" কাজ করে। সাধারণ ইউজার লগইন ছাড়া
    টুলটি খুলতে পারবে না, কিন্তু প্রযুক্তি জানা কেউ পেজের সোর্স কোড সরাসরি দেখে/কপি করে টুলটি চালাতে পারে।
    টুলটি পুরোপুরি ব্রাউজারেই চলে (সার্ভারে কিছু যায় না), তাই এটা বাস্তবে অ্যাক্সেস-নিয়ন্ত্রণ নয়, ইউজার-তালিকা
    রাখা ও ব্লক করার ব্যবস্থা। পুরোপুরি সুরক্ষিত রাখতে হলে সার্ভার-সাইড হোস্টিং লাগবে।
 3. ADMIN_PASSWORD অবশ্যই বদলে নিন, আর অ্যাডমিন পেজের লিংক কাস্টমারদের দেবেন না।
